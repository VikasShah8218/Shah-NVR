Record cameras where they are. Watch them from anywhere.

Shah-NVR is an open-source, ONVIF-native video recorder built as a cluster. One lightweight control plane manages your whole estate, while media nodes record and stream video close to the cameras. No central video bottleneck, and no mandatory transcoding.

View source on GitHub Run it locally

From a pilot deployment: one media node recording 35 ONVIF cameras.

Centralize coordination. Distribute the video.

Traditional NVRs put ingest, recording, storage and playback in one box, and when that box is full you replace it. Shah-NVR splits the job: the Central Manager handles metadata and decisions, and media nodes handle every byte of video.

Grow one node at a time

Each node advertises its capacity and the scheduler places cameras on healthy nodes. Ten nodes at about 100 cameras each is the illustrative path to 1,000 cameras, under one interface.

Keep recording through outages

Nodes cache their assignments and queue metadata in local SQLite. If the Central Manager goes offline, recording continues and the catalog catches up later.

Play back across nodes without copies

The Central Manager builds an HLS playlist that points at whichever nodes hold each segment. Viewers fetch the original fMP4 bytes directly.

Everything an operator needs, built on open standards

Discovery, PTZ, recording, playback and recovery all speak ONVIF, so cameras from different vendors work side by side.

Camera onboarding and control

  • WS-Discovery or manual add, with bulk onboarding under one login
  • Main and substream selection with snapshot preview and clock check
  • H.264/H.265 encoder settings with review-before-apply and restore
  • PTZ with pan, tilt, zoom, speed, presets and home

Live monitoring

  • WebRTC and low-latency HLS in the browser, native RTSP on desktop
  • Substream-aware grids that save bandwidth and decoders
  • Digital zoom and pan up to 4×, live audio, snapshots
  • Per-operator LAN or public routing that doesn't affect anyone else

Recording and playback

  • Continuous fragmented MP4 recording through MediaMTX
  • Timeline with coverage, gaps and segment origin
  • Seamless playback across chunks and across nodes
  • Exports up to four hours, lossless or compressed, CPU or GPU

Resilience and recovery

  • Heartbeats, ownership leases and automatic reassignment
  • Startup scanning recovers files after an interruption
  • ONVIF Profile G backfill fills gaps from a camera's SD card
  • Per-camera retention plus emergency disk protection

Storage you control

  • Multiple recording volumes with fill order and quotas
  • Video stays on node disks, and only the index goes central
  • Add disks or nodes instead of replacing an appliance

Works with other systems

  • A media node can act as a virtual ONVIF NVR for external VMS
  • Protected RTSP that never reveals original camera passwords
  • Open FastAPI endpoints with generated OpenAPI contracts

Size your deployment

Estimate bandwidth and storage from your cameras' average bitrate. These are video-only planning figures, so add headroom for audio, overhead and live viewing.

Camera ingress200 Mbps
Storage per day2.16 TB
Storage for retention64.8 TB
Media nodes at 100 cameras each1

Formula: cameras × average Mbps × 10.8 GB per day. The 100-camera default is a scheduling limit, not a performance guarantee, so benchmark your own hardware.

Run it locally

Everything can run on one Windows or Ubuntu machine for development or a single-site pilot.

You'll need Python 3.12+, PostgreSQL, Node.js, a MediaMTX binary for your platform, FFmpeg on your PATH, and libmpv for the Windows desktop client.

Start the Central Manager

Set your PostgreSQL connection in .env, initialize the database once, then start the API. Interactive docs open at localhost:8000/docs.

cd central_manager
cp .env.example .env
pip install -r requirements.txt
aerich init-db
python main.py

Start a media node

Set NODE_NAME, CENTRAL_URL, MEDIAMTX_BIN and RECORDINGS_DIR. The node starts MediaMTX, registers itself and begins its heartbeat.

cd media_node
cp .env.example .env
pip install -r requirements.txt
python main.py

Open the web client

cd nvr_client
npm install
npm run dev

Or use the Windows desktop client

Put libmpv-2.dll in nvr_desktop/bin/ first. See the desktop README for details.

cd nvr_desktop
py main.py

Where the project stands

Distributed recording, playback, ONVIF, PTZ, audio, storage, failover and edge recovery are implemented. Shah-NVR is under active development.

Treat it as pilot software for now

Authentication, role-based access, TLS and encrypted camera credentials aren't integrated yet. Until they are:

  • Don't expose the APIs directly to the internet
  • Use a VPN or a protected reverse proxy
  • Isolate camera networks and replace example secrets
  1. Sustained, failure-oriented soak testing
  2. Authentication, RBAC, encrypted credentials and TLS
  3. Ubuntu services, packaging, backup, restore and rollback
  4. Alerting, auditing and Prometheus-compatible metrics
  5. PostgreSQL partitioning for large estates
  6. Per-node and full-cluster performance certification
  7. Formal ONVIF conformance
